ModelC4
VendorUbisys
DescriptionControl unit C4
Exposesaction
Picture

Notes

일반 사항

ubisys C4 리모컨 유닛은 주로 다른 Zigbee 디바이스에 직접 바인딩하여 제어하는 용도로 설계된 것 같습니다. 따라서 단순한 "클릭" 이벤트 등을 내보내지 않고, 최대 6개의 엔드포인트(조명용 on/off, 레벨, 씬 클러스터 4개 + 창문 커버 제어용 2개)에서 on, off, toggle, cover up, cover down 등의 Zigbee 명령을 전송하도록 설정할 수 있습니다. Zigbee2MQTT와 함께 사용하면 모든 엔드포인트가 코디네이터에 자동으로 바인딩됩니다. 따라서 모든 동작이 코디네이터로 전송되어 MQTT로 전달되며, 수동으로 바인딩된 다른 디바이스로도 Zigbee를 통해 직접 전송됩니다 (자세한 내용은 바인딩 참고). 공장 초기화 상태의 ubisys C4는 각 입력에 대해 해당 엔드포인트(1~4)에서 toggle 명령을 전송합니다. 따라서 추가 입력 설정 없이도 연결된 순간 스위치의 기본 키 입력을 Zigbee2MQTT를 통해 처리할 수 있습니다.

입력 구성

대부분의 ubisys 디바이스의 입력은 상태 전환(예: '해제' → '눌림')을 Zigbee 명령(예: 'toggle')에 매핑하는 방식으로 매우 유연하게 구성할 수 있습니다. 이는 입력이 로컬 부하를 제어하는 방식에도 적용됩니다(C4 이외의 ubisys 디바이스에 해당).

템플릿

configure_device_setup과 input_action_templates JSON 속성을 사용하여 zigbee2mqtt/FRIENDLY_NAME/set에 발행하면 템플릿을 이용해 입력을 구성할 수 있습니다. 이를 통해 input_actions의 세부 사항을 깊이 파고들지 않고도 일반적인 사용 사례를 구성할 수 있습니다 (아래 직접 구성(Raw Configuration) 참고).

유효한 템플릿 유형:

  • toggle: 푸시 버튼 입력 1개로 조명(또는 유사한 액추에이터)의 상태를 토글합니다. 버튼을 누를 때마다 'toggle' 명령이 전송됩니다.
  • toggle_switch: 고정형 스위치 1개로 토글합니다. 스위치를 켜거나 끌 때 'toggle' 명령이 전송됩니다.
  • on_off_switch: 고정형 스위치 1개로 켜고 끕니다. 스위치를 켜면 'on' 명령이, 끄면 'off' 명령이 전송됩니다. 그룹을 제어할 때 조명이 동기화된 상태를 유지하는 데 유용합니다.
  • on: 버튼을 누를 때마다 'on' 명령만 전송합니다. 예를 들어 (물리적) 알람 시스템이 침입을 감지했을 때 모든 조명을 켜기 위해 C4를 릴레이가 있는 다른 물리적 디바이스의 직접 인터페이스로 사용할 때 유용합니다.
  • off: 버튼을 누를 때마다 'off' 명령만 전송합니다(on도 참고).
  • dimmer_single: 푸시 버튼 1개로 조명 상태를 토글하고 레벨도 제어합니다. 짧게 누르면 'toggle' 명령이 전송되고, 길게 누르면 레벨이 교대로 올라가거나 내려갑니다.
  • dimmer_double: 푸시 버튼 2개로 조명을 켜고 끄며 레벨도 제어합니다. 첫 번째 입력에서 짧게 누르면 'on' 명령이, 길게 누르면 'move level up' 명령이 전송됩니다. 두 번째 입력에서 짧게 누르면 'off' 명령이, 길게 누르면 'move level down' 명령이 전송됩니다.
  • cover: 푸시 버튼 2개로 커버를 제어합니다. 첫 번째 입력을 누르면 'move up' 명령이 전송되고, 1초 이내에 놓으면 'stop' 명령이 전송됩니다. 두 번째 입력도 동일한 방식으로 'move down'과 'stop' 명령이 전송됩니다. 이를 통해 짧게 눌러 블라인드 틸트를 제어하거나 길게 눌러 완전히 올리거나 내릴 수 있습니다.
  • cover_switch: 고정형 스위치 2개로 커버를 제어합니다. cover와 유사하지만, 스위치를 끄면 항상 'stop' 명령이 전송됩니다.
  • cover_up: 버튼을 누를 때마다 'move up' 명령만 전송합니다(on도 참고).
  • cover_down: 버튼을 누를 때마다 'move down' 명령만 전송합니다(on도 참고).
  • scene: 푸시 버튼으로 씬을 선택합니다(씬 ID 사용). 짧게 누르면 scene_id를 사용하여 'recall scene' 명령이 전송되고, scene_id_2가 있으면 길게 눌렀을 때 scene_id_2를 사용하여 동일한 명령이 전송됩니다.
  • scene_switch: 고정형 스위치로 씬을 선택합니다. scene과 매우 유사하며, 스위치를 켜면 scene_id가, 끄면 scene_id_2가 전송됩니다(설정된 경우).

공통 속성:

  • input: 선택 사항, 템플릿에 사용할 입력을 선택합니다. 지정하지 않으면 첫 번째 템플릿은 입력 0을 사용하고, 이후 템플릿마다 자동으로 증가합니다. 템플릿이 입력 2개를 사용하는 경우 input과 input+1이 사용되고, 다음 템플릿은 input+2를 사용합니다.
  • inputs: 선택 사항, 입력 2개를 사용하는 템플릿에서 두 입력을 각각 선택합니다. 예를 들어 배선이 다르게 된 경우 위/아래 입력을 바꿀 수 있습니다. 다음 템플릿은 Math.max(...inputs)+1을 사용합니다.
  • endpoint: 선택 사항, 명령 전송에 사용할 아웃바운드 엔드포인트를 선택합니다. C4는 엔드포인트 1부터 시작하는 아웃바운드 엔드포인트만 포함합니다(위 참고). 다른 ubisys 디바이스에서 엔드포인트 1은 보통 부하를 제어하는 인바운드 엔드포인트이지만, 2 또는 3부터 아웃바운드 엔드포인트도 포함되며 기본적으로 해당 부하 제어 엔드포인트에 바인딩되어 있으나 변경(예: 스위치에서 푸시 버튼으로)하거나 바인딩 해제 후 재바인딩하여 예를 들어 S1-R 또는 D1의 두 번째 입력으로 다른 조명을 제어할 수도 있습니다. 지정하지 않으면 첫 번째 템플릿은 해당 디바이스의 첫 번째 사용 가능한 아웃바운드 엔드포인트를 사용하고, 이후 템플릿마다 자동으로 증가합니다. C4의 경우, 커버 템플릿은 엔드포인트 5부터 시작합니다(엔드포인트 1~4에 window covering 클러스터가 없어 조명 등에만 사용할 수 있으므로).

사용된 입력 및 엔드포인트는 Zigbee2MQTT 로그에도 출력됩니다(억제되지 않도록 경고로 표시됨).

디머 템플릿 전용 속성:

  • no_onoff_down: 선택 사항, 레벨을 완전히 내릴 때 조명을 자동으로 끄지 않도록 전송되는 명령을 변경합니다. 조명을 끄지 않고 완전히 어둡게 할 때 유용합니다.
  • no_onoff_up: 선택 사항, 레벨을 올릴 때 조명을 자동으로 켜지 않도록 전송되는 명령을 변경합니다.
  • no_onoff: 선택 사항, no_onoff_up과 no_onoff_down의 조합입니다.
  • rate: 선택 사항(기본값 50), 레벨을 올리거나 내릴 때 초당 스텝 수를 지정합니다.

씬 템플릿 전용 속성:

  • scene_id: 필수, 템플릿의 기본 기능(짧게 누르기 또는 스위치 켜기)에 전송할 씬 ID를 지정합니다.
  • group_id: 'recall scene'을 전송할 그룹 ID를 지정합니다(configuration.yaml / groups의 그룹 정의 및 씬 저장 시 사용된 것과 동일해야 합니다). 이후 씬 템플릿에서는 생략 가능합니다.
  • scene_id_2: 선택 사항, 있으면 템플릿의 보조 기능(길게 누르기 또는 스위치 끄기)에 전송할 씬 ID를 지정합니다.
  • group_id_2: 선택 사항, scene_id_2와 함께 전송할 그룹 ID를 지정합니다. group_id와 다른 경우에만 필요합니다.

C4에서는 대부분의 템플릿 유형(씬 제어 제외)을 사용하려면 해당 아웃바운드 엔드포인트도 하나 이상의 대상 디바이스에 바인딩해야 합니다 (아래 바인딩 참고).

또한 input_action_templates을 사용하여 성공적으로 쓸 수 있는 데이터 양에 크기 제한이 있을 수 있으므로, 이론적으로 가능한 모든 조합이 실제로 작동하지 않을 수 있습니다.

템플릿 예시

"//_comment" 필드는 주석용이며, 다른 추가 JSON 속성처럼 무시됩니다. 일반 JavaScript 주석(//)은 유효한 JSON이 아니어서 Zigbee2MQTT가 오류를 발생시키므로 이 방식을 사용합니다.

C4 기본 구성

{
    "configure_device_setup": {
        "input_action_templates": [
            {
                "//_comment": "will automatically use input 0 and endpoint 1",
                "type": "toggle"
            },
            {
                "//_comment": "will automatically use input 1 and endpoint 2",
                "type": "toggle"
            },
            {
                "//_comment": "will automatically use input 2 and endpoint 3",
                "type": "toggle"
            },
            {
                "//_comment": "will automatically use input 4 and endpoint 4",
                "type": "toggle"
            }
        ]
    }
}

입력 1(위)과 0(아래)으로 디밍 조명 제어, 입력 3으로 다른 조명 토글

{
    "configure_device_setup": {
        "input_action_templates": [
            {
                "//_comment": "will automatically use endpoint 1",
                "type": "dimmer_double",
                "inputs": [1, 0]
            },
            {
                "//_comment": "will automatically use endpoint 2",
                "type": "toggle",
                "input": 3
            }
        ]
    }
}

D1에서 별도의 위/아래 푸시 버튼 사용

{
    "configure_device_setup": {
        "input_action_templates": [
            {
                "//_comment": "will automatically use inputs 0 and 1 and endpoint 2 (first outbound endpoint on a D1)",
                "type": "dimmer_double"
            }
        ]
    }
}

J1에서 푸시 버튼 대신 고정형 스위치 사용

{
    "configure_device_setup": {
        "input_action_templates": [
            {
                "//_comment": "will automatically use inputs 0 and 1 and endpoint 2 (first outbound endpoint on a J1)",
                "type": "cover_switch"
            }
        ]
    }
}

입력 0과 1로 디밍 조명 제어, 입력 3과 4로 씬 불러오기

{
    "configure_device_setup": {
        "input_action_templates": [
            {
                "//_comment": "will automatically use inputs 0 and 1 and endpoint 1",
                "type": "dimmer_double"
            },
            {
                "//_comment": "will automatically use input 3 (endpoint does not really matter for scenes)",
                "type": "scene",
                "group_id": 1000,
                "scene_id": 10
            },
            {
                "//_comment": "will automatically use input 4 and group id 1000",
                "type": "scene",
                "scene_id": 11
            }
        ]
    }
}

직접 구성(Raw Configuration)

zigbee2mqtt/FRIENDLY_NAME/set에 발행하여 다음 디바이스 속성을 설정하면 입력을 직접 구성할 수 있습니다:

{
    "configure_device_setup": {
        "input_configurations": [0, 0, 0, 0],
        "input_actions": [
            [0, 13, 1, 6, 0, 2],
            [1, 13, 2, 6, 0, 2],
            [2, 13, 3, 6, 0, 2],
            [3, 13, 4, 6, 0, 2]
        ]
    }
}

이 속성에 대한 자세한 내용은 ubisys C4 기술 참고 매뉴얼의 "7.8.5. Device Setup Cluster (Server)" 챕터(또는 C4가 아닌 경우 해당 디바이스의 ubisys 참고 매뉴얼)와 "Zigbee Device Physical Input Configurations Integrator's Guide"(ubisys에 직접 요청하여 얻을 수 있음)를 참고하세요. input_configurations 및 input_actions 배열의 각 요소는 단일 바이트에 해당합니다. 따라서 1바이트보다 큰 필드(예: input_actions의 "ClusterID" 필드)는 배열의 여러 요소로 표현되며, 전송되는 구성에 따라 배열 길이가 달라질 수 있습니다.

input_actions에 성공적으로 쓸 수 있는 데이터 양에 크기 제한이 있을 수 있으므로, 이론적으로 가능한 모든 구성이 실제로 작동하지 않을 수 있습니다.

zigbee2mqtt/FRIENDLY_NAME/get/configure_device_setup에 발행하면 구성 속성 값을 디바이스에서 다시 읽을 수도 있습니다. configure_device_setup이 항상 발행된 페이로드에 표시되지 않도록 하려면, 디바이스 옵션에서 filtered_cache를 설정하여 캐싱을 방지할 수 있습니다.

devices:
  '0x0000000000000000':
    friendly_name: 'my_c4_controller'
    filtered_cache:
      - configure_device_setup

바인딩

대부분의 input_actions 및 input_action_templates(씬 제어 제외)는 대상 디바이스를 직접 참조하지 않고 특정 아웃바운드 엔드포인트의 바인딩 테이블을 활용합니다(C4의 경우 위 일반 사항 참고, 다른 ubisys 디바이스는 해당 참고 매뉴얼 참고). C4의 경우 Zigbee2MQTT가 항상 모든 엔드포인트를 코디네이터에 자동으로 바인딩합니다(Zigbee2MQTT가 버튼 누름을 MQTT로 전달할 수 있도록). 하지만 다른 Zigbee 디바이스나 그룹을 직접 제어하려면 사용된 아웃바운드 엔드포인트를 대상(디바이스 또는 그룹)에 바인딩해야 합니다.

바인딩(또는 바인딩 해제) 시에는 소스로 아웃바운드 엔드포인트를 명시적으로 지정하는 것이 중요합니다. 예: zigbee2mqtt/bridge/request/device/bind 페이로드 {"from": "SOURCE_DEVICE_FRIENDLY_NAME/2", "to": "TARGET"} (특정 엔드포인트 바인딩도 참고). 엔드포인트는 숫자 형식으로 지정할 수 있으며, 대상 디바이스에는 보통 엔드포인트를 지정할 필요가 없습니다.

C4 이외의 ubisys 디바이스에서는 이를 통해 보조 입력으로 다른 디바이스를 제어할 수도 있습니다. 예시: D1의 보조 입력(공장 설정에서 아웃바운드 엔드포인트 3 사용)으로 별도의 Zigbee 전구 제어:

mosquitto_pub -t zigbee2mqtt/bridge/request/device/bind -m '{"from": "DIMMER_FRIENDLY_NAME/3", "to": "ANOTHER_BULB_FRIENDLY_NAME"}'

분리(Decoupling)

C4 이외의 ubisys 디바이스에서는 로컬 입력을 로컬 출력에서 완전히 분리할 수도 있습니다. 예시: 스위치 입력을 로컬 부하에서 바인딩 해제하고, 전구에 전원을 차단하지 않고 조명 그룹을 제어하는 데 사용(스위치 출력은 여전히 Zigbee를 통해, 예: Zigbee2MQTT를 통한 MQTT로 제어 가능):

mosquitto_pub -t zigbee2mqtt/bridge/request/device/unbind -m '{"from": "SWITCH_FRIENDLY_NAME/2", "to": "SWITCH_FRIENDLY_NAME"}'
mosquitto_pub -t zigbee2mqtt/bridge/request/device/bind -m '{"from": "SWITCH_FRIENDLY_NAME/2", "to": "GROUP_NAME"}'

원래 동작을 복원하려면 그룹 바인딩을 해제하고 디바이스를 재바인딩합니다:

mosquitto_pub -t zigbee2mqtt/bridge/request/device/unbind -m '{"from": "SWITCH_FRIENDLY_NAME/2", "to": "GROUP_NAME"}'
mosquitto_pub -t zigbee2mqtt/bridge/request/device/bind -m '{"from": "SWITCH_FRIENDLY_NAME/2", "to": "SWITCH_FRIENDLY_NAME"}'

Options

How to use device type specific configuration

  • simulated_brightness: Simulate a brightness value. If this device provides a brightness_move_up or brightness_move_down action it is possible to specify the update interval and delta. The action_brightness_delta indicates the delta for each interval. Example:
simulated_brightness:
  delta: 20 # delta per interval, default = 20
  interval: 200 # interval in milliseconds, default = 200

Action (enum)

Triggered action (e.g. a button click). Value can be found in the published state on the action property. It's not possible to read (/get) or write (/set) this value. The possible values are: toggle_s1, toggle_s2, toggle_s3, toggle_s4, on_s1, on_s2, on_s3, on_s4, off_s1, off_s2, off_s3, off_s4, recall_*_s1, recal_*_s2, recall_*_s3, recal_*_s4, brightness_move_up_s1, brightness_move_up_s2, brightness_move_up_s3, brightness_move_up_s4, brightness_move_down_s1, brightness_move_down_s2, brightness_move_down_s3, brightness_move_down_s4, brightness_stop_s1, brightness_stop_s2, brightness_stop_s3, brightness_stop_s4, cover_open_s5, cover_close_s5, cover_stop_s5, cover_open_s6, cover_close_s6, cover_stop_s6.
