# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

zigbee2mqtt.io is the official documentation site for Zigbee2MQTT, built with **VuePress v2** (`@vuepress/bundler-vite`). The defining characteristic of this repo is that most content — the ~5000 device pages and several config/overview pages — is **auto-generated by the `docgen/` TypeScript scripts** from the `zigbee-herdsman-converters` package, not handwritten.

Package manager is **pnpm** (`pnpm@10.12.1`). Node version is **24** (`.nvmrc`; CI uses 24).

## Commands

- `pnpm i --frozen-lockfile` — install deps
- `pnpm run dev` — dev server **without** device pages (fast; sets `EXCLUDE_DEVICES=yes`). Default for most doc work.
- `pnpm run dev:devices` — dev server **with** all device pages (slow; needs ~12 GB heap)
- `INCLUDE_DEVICE=<MODEL> pnpm run dev` — build only one device page during dev
- `DEV_PORT=<port> pnpm run dev` — change port (default 8080)
- `pnpm run build` — production static build → `dist/`
- `pnpm run docgen` — regenerate all device/settings/supported-devices pages, then runs `prettier --write`
- `pnpm run pretty:check` / `pnpm run pretty:write` — Prettier check / apply (this is the only "lint")
- `pnpm run test` — run the custom validation suite

### Tests

There is **no** Jest/Vitest. `pnpm run test` runs `ts-node docgen/tests/index.ts`, a custom runner that executes 5 checks in parallel (device images, image size, internal links, Notes comment format, Notes HTML tags) and exits 1 if any fail. There is **no built-in single-test filter**; run the whole suite, or invoke a specific check module under `docgen/tests/` directly with ts-node.

## Linting / Formatting

The only style tool is **Prettier 3** (no ESLint, no markdownlint). Config in `.prettierrc`: `tabWidth: 4`, `singleQuote`, `trailingComma: all`, `bracketSpacing: false`, `printWidth: 150`. A **Husky pre-commit hook runs `pnpm run pretty:check`**, so commits fail on unformatted files — run `pnpm run pretty:write` before committing.

`docs/devices/*.md` and image dirs are in `.prettierignore`.

> **Known inconsistencies**: `.editorconfig` says `indent_size = 2` but `.prettierrc` uses `tabWidth: 4` — Prettier wins. README mentions Node 20 but `.nvmrc`/CI use 24 — prefer 24.

## Architecture

Two-axis content model: handwritten guides vs. docgen-generated device data.

### `docs/` — VuePress content root

- `docs/devices/*.md` — ~5000 **auto-generated** device pages. **Do not edit except the `## Notes` section** between `<!-- Notes BEGIN -->` and `<!-- Notes END -->`, which is handwritten and preserved across regeneration. Sidebar is disabled for this directory.
- `docs/supported-devices/README.md` and `docs/guide/configuration/all-settings.md` — **auto-generated; do not edit** (files are marked "do not edit").
- `docs/guide/**`, `docs/advanced/**` — handwritten guides; edit these directly.
- `docs/.vuepress/` — Vue components (`Configurator.vue`, etc.) and styles (`palette.scss`).

### `docgen/` — code generator (runs separately from the site build)

- `index.ts` — entry point for `pnpm run docgen`: removes obsolete device pages, then in parallel generates device pages (concurrency 20), the supported-devices page, and the settings page.
- `generate_device.ts` — writes one `docs/devices/<normalizedModel>.md` per device model; **preserves the existing `## Notes` block and `addedAt` value** when regenerating.
- `generate_supported-devices.ts` — emits a JSON array into `window.ZIGBEE2MQTT_SUPPORTED_DEVICES` + a `<SupportedDevices />` component (rendered client-side by `supported-devices-component/`).
- `generate_settings.ts` — fetches Zigbee2MQTT's `settings.schema.json` remotely and writes `docs/guide/configuration/all-settings.md`.
- `device_page_notes/`, `device_page_warnings/` — vendor-specific notes/warnings injected programmatically into device pages.
- `constants.ts` — `devicesBaseDir = docs/devices`, `imageBaseDir = public/images/devices`.

### `public/images/devices/`

Device images: `<normalizedModel>.png` (square PNG, 512 or 150 px). White-label devices fall back to the original device's image. These are what the "image for …" commits add.

### Root config files

`navbar.ts`, `sidebar.ts`, `vuepress.config.ts`, `getBase.ts` — nav/sidebar/VuePress config. `vuepress.config.ts` honors `EXCLUDE_DEVICES`/`INCLUDE_DEVICE` env vars to skip or filter the 5000 device pages during dev.

### Device data source

Device definitions come from the **`zigbee-herdsman-converters`** npm dependency. Adding _support_ for a new device happens in **that** repo, not here; `pnpm run docgen` then generates the page. See `docs/advanced/support-new-devices/`.

## Common Contribution Types

1. **Improve device docs** → edit only the `## Notes` section of `docs/devices/<MODEL>.md`.
2. **Add a device image** → add `public/images/devices/<model>.png` (square PNG).
3. **Write/edit guides** → `docs/guide/**`, `docs/advanced/**`.
4. **Vendor-wide notes/warnings** → add modules under `docgen/device_page_notes/` or `docgen/device_page_warnings/`, then register them in `docgen/index.ts`.
