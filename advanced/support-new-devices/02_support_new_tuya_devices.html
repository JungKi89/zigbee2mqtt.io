새 Tuya 기기 지원 추가

Tuya 기기는 커스텀 manuSpecificTuya cluster를 사용합니다. 아래 지침은 이를 더 잘 이해하고 기능 검색을 돕는 도구를 제공합니다.

지침

1. 기본 설정 부분

external converter 설정 방법에 대한 기본 방법을 읽어보세요.

2. 기기 추가

Tuya 기기에 대한 지원 추가는 약간 다릅니다. 예를 들어 TS0601 모델 ID를 지원하려면 다음과 같은 external converter를 만들어야 합니다:

const fz = require('zigbee-herdsman-converters/converters/fromZigbee');
const tz = require('zigbee-herdsman-converters/converters/toZigbee');
const exposes = require('zigbee-herdsman-converters/lib/exposes');
const reporting = require('zigbee-herdsman-converters/lib/reporting');
const modernExtend = require('zigbee-herdsman-converters/lib/modernExtend');
const e = exposes.presets;
const ea = exposes.access;
const tuya = require('zigbee-herdsman-converters/lib/tuya');

const definition = {
    // 많은 Tuya 기기가 동일한 modelID를 사용하지만 다른 datapoint를 사용하므로
    // zigbeeModel 대신 fingerprint를 제공해야 합니다
    fingerprint: [
        {
            // 다음 메시지의 모델 ID: Device with modelID 'TS0601' is not supported
            // 경우에 따라 이름 끝에 �을 추가해야 할 수도 있습니다
            modelID: 'TS0601',
            // 다음 메시지의 제조사 이름: Device with modelID 'TS0601' is not supported.
            manufacturerName: '_TZE200_d0yu2xgi',
        },
    ],
    model: 'TS0601_new',
    vendor: 'Tuya',
    description: '여기에 기기 설명을 입력하세요',
    extend: [
        tuya.modernExtend.tuyaBase({
            dp: true,
            // 기기에 시계가 있는 경우 이 줄을 활성화하세요. 시간이 `1970`으로
            // 잘못 표시되면 `2000`으로 시도해 보세요.
            // timeStart: "1970",
        }),
    ],
    exposes: [
        // 여기에 기기가 노출하는 모든 기능을 입력해야 합니다
    ],
    meta: {
        // 모든 datapoint는 여기에 들어갑니다
        tuyaDatapoints: [],
    },
};

module.exports = definition;

3. Tuya datapoint 이해

manuSpecificTuya cluster의 dataReport과 dataResponse 유형에는 고유한 형식이 있습니다:

    {name: 'seq', type: DataType.uint16},
    {name: 'dpValues', type: BuffaloZclDataType.LIST_TUYA_DATAPOINT_VALUES},

seq는 payload의 트랜잭션 번호입니다. dpValues는 "Data Points" 배열입니다 (유형: TuyaDataPointValue). 이러한 datapoint 값은 다음으로 구성됩니다:

dp: DataType.uint8;
datatype: DataType.uint8;
data: Buffer;
  • dp는 Tuya 기기의 핵심인 소위 "Data Point ID"입니다. 기기 관점에서 DPID는 기기가 제공하는 기능입니다.
  • datatype은 data 필드에 포함된 데이터 유형입니다. node_modules/zigbee-herdsman-converters/lib/tuya.js의 dataTypes를 참조하세요.

일부 datapoint는 '보고 전용'(기기 내에서 발생하는 변경 사항을 보고함)이고 다른 것들은 '발행 및 보고'(자체적으로 보고할 수 있지만 설정 시 보고로 응답하기도 함)입니다. Data point는 모든 Tuya 기기에서 통일되지 않으므로 기기마다 다를 수 있습니다.

4. Datapoint 매핑

이제 tuyaDatapoints에서 datapoint를 매핑해야 합니다. debug 로깅을 활성화하여 Zigbee2MQTT를 시작하고 기기에서 일부 동작을 트리거합니다. 그러면 다음과 같은 로그가 표시됩니다:

Zigbee2MQTT:debug 2022-11-30 18:29:19: Datapoint '106' with value '77' not defined for '_TZE200_d0yu2xgi'

다음으로 이 datapoint가 무엇을 의미하는지 확인해야 합니다 (이 예에서는 106). 다양한 방법이 있습니다:

  • Tuya gateway를 사용하여 Tuya datapoint 찾기 (가장 쉽지만 Tuya gateway 필요)
  • 이미 지원되는 Tuya 기기에 이 datapoint가 매핑되어 있는지 확인 (검색)
  • 값을 기반으로 추측

이 기기에서 datapoint 106이 습도라는 것을 알고 있으면 external converter의 exposes 및 tuyaDatapoints 섹션을 업데이트할 수 있습니다:

    exposes: [
        e.humidity(), // <- 습도 expose 추가
    ],
    meta: {
        tuyaDatapoints: [
            [106, 'humidity', tuya.valueConverter.raw], // <- datapoint 매핑
        ],
    },

매핑된 datapoint의 값은 다음과 같습니다:

  1. Datapoint (이 예에서는 106)
  2. 상태에 이 값이 게시되어야 하는 키 (이 예에서는 humidity)
  3. Value converter - 게시하기 전에 수신된 값을 변환합니다 (이 예에서는 tuya.valueConverter.raw). 더 많은 value converter가 있습니다. 예시:
    • 값을 10으로 나누어야 하는 경우 tuya.valueConverter.divideBy10 사용
    • 값을 문자열에 매핑해야 하는 경우 tuya.valueConverterBasic.lookup({'single': 0, 'double': 1, 'hold': 2}) 사용
    • 더 많은 예시는 tuya.ts에서 tuyaDatapoints 검색

모든 datapoint에 대해 반복합니다.

6. Pull Request 생성

다음 릴리스에서 즉시 지원되도록 새 기기 정의를 Zigbee2MQTT에 기여하려면 다음 단계를 따르세요: Pull Request 생성.

7. 보너스: 제조사 연락하기

Tuya 호환 기기의 제조사에 연락할 때 기기의 Zigbee 프로토콜을 요청하지 마세요. 그들은 구매한 Tuya 라디오가 Zigbee를 통해 어떻게 통신하는지 일반적으로 모릅니다. 대신 기기의 UART 프로토콜을 요청하면 더 나은 협력을 얻을 수 있습니다. DPID와 기능에 대한 데이터 형식도 물어볼 수 있습니다.

8. 보너스 2: 추가 읽기

기기가 Tuya Zigbee 라디오 모듈과 통신하는 방법에 대한 자세한 내용은 여기에서 읽을 수 있습니다.

Tuya 기기 감지 수정

기기가 완전히 작동하지만 잘못된 사진 및/또는 설명이 있는 경우 감지를 쉽게 수정할 수 있습니다:

  1. 먼저 Zigbee2MQTT 프론트엔드에서 기기 -> 정보 페이지로 이동하여 이 기기의 Model(Zigbee model이 아님!)을 확인합니다.
  2. 1단계의 Model을 기반으로 정의 파일 중 하나에서 이 기기의 정의를 찾습니다. 예: tuya.ts.
  3. 편집 아이콘 클릭
  4. 정의에 whiteLabel을 추가합니다 (예시). 형식은 tuya.whitelabel("VENDOR", "MODEL", "DESCRIPTION", ["MANUFACTURER_NAME"])입니다.
    • VENDOR: 기기의 제조사. 모르는 경우 Tuya를 사용하세요.
    • MODEL: 기기 또는 제품 페이지에 표시된 모델 번호
    • DESCRIPTION: 기기 설명
    • MANUFACTURER_NAME: 프론트엔드 -> 기기 -> 정보 페이지 -> Zigbee Model 아래에서 확인할 수 있습니다. 예: _TZ3000_cphmq0q7 또는 _TZE200_eegnwoyw.
  5. 변경 사항을 커밋하고 Pull Request 생성
  6. 문서용 사진 제출 (가이드)
